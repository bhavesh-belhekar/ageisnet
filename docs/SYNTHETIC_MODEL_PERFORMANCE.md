# Flow model: detailed synthetic performance report

**Status:** reproducible smoke test only. This report measures generated
feature rows and does not establish performance on real network traffic.

## Executive results

The Isolation Forest was fit on 1,000 generated normal windows. On a separate
normal validation set of 250 windows, `model.predict()` marked 13 as anomalous
(5.2% false-positive rate). A 400-row labeled synthetic holdout contained 250
normal and 150 attack windows.

At the application's configured anomaly score threshold (`0.52`), the model
detected only 3 of the 150 attacks. Calibrating a candidate threshold from the
90th percentile of the normal validation score distribution (`0.492817`) gave
better results on this generated holdout. The threshold comparison is:

| Metric | Configured `0.52` | Validation-calibrated `0.492817` |
|---|---:|---:|
| True positives | 3 | 150 |
| False positives | 1 | 18 |
| False negatives | 147 | 0 |
| True negatives | 249 | 232 |
| Accuracy | 63.00% | 95.50% |
| Precision | 75.00% | 89.29% |
| Recall / attack detection rate | 2.00% | 100.00% |
| F1 | 3.90% | 94.34% |
| Specificity | 99.60% | 92.80% |
| Normal false-positive rate | 0.40% | 7.20% |
| Attack false-negative rate | 98.00% | 0.00% |
| Negative predictive value | 62.88% | 100.00% |
| Balanced accuracy | 50.80% | 96.40% |
| Matthews correlation coefficient | 0.0778 | 0.9103 |

The configured-threshold result shows a serious synthetic recall gap. The
calibrated result is specific to this generated distribution and must not be
read as expected production performance.

## Dataset and training setup

The data were generated by `scripts/generate_synthetic_flow_data.py` with seed
`20261115`, using the six feature columns expected by the flow model:

1. `total_bytes_sent`
2. `total_bytes_received`
3. `connection_count`
4. `unique_dst_ports`
5. `unique_dst_ips`
6. `window_seconds`

The normal generator uses a two-mode benign traffic mixture, log-normal byte
volumes, Poisson connection and port counts, categorical destination counts,
and a uniform event span. The 150 holdout attack windows combine generated
high-outbound/low-inbound exfiltration, port scans, and destination spread.
Labels are binary (normal or attack); subtype labels were not retained, so
per-attack-class recall cannot be calculated from this run.

| Split | Rows | Contents | Use |
|---|---:|---|---|
| Train | 1,000 | Synthetic normal only | Fit scaler and Isolation Forest |
| Normal validation | 250 | Separate synthetic normal rows | Report normal false positives and derive candidate threshold |
| Labeled holdout | 400 | 250 normal + 150 attacks | Report classification metrics |

Training used Isolation Forest with 100 estimators, contamination `0.05`,
random seed `42`, `StandardScaler`, and configured percentile caps. Byte
transfer features remain uncapped at inference so extreme transfers can still
affect the score. The artifact was generated with scikit-learn `1.6.1` and
SHAP `0.47.2`.

## Metric definitions

The positive class is an attack window. A predicted anomaly is a positive
prediction.

- **Precision:** `TP / (TP + FP)`; among flagged windows, the fraction labeled attack.
- **Recall:** `TP / (TP + FN)`; among attack windows, the fraction flagged.
- **F1:** harmonic mean of precision and recall.
- **Specificity:** `TN / (TN + FP)`; the fraction of normal windows left unflagged.
- **False-positive rate:** `FP / (FP + TN)`.
- **False-negative rate:** `FN / (FN + TP)`.
- **Negative predictive value:** `TN / (TN + FN)`.
- **Balanced accuracy:** mean of recall and specificity.
- **Matthews correlation coefficient:** correlation between binary labels and predictions; 1 is perfect, 0 is chance-level, and -1 is fully reversed.

Accuracy alone is insufficient here because it can obscure a model that misses
nearly all attacks. Recall, false-positive rate, F1, and the confusion matrix
are more informative for this test.

## Threshold details

The runtime policy currently uses `0.52`. In the model's inference mapping,
`score = 1 / (1 + exp(decision_function))`; a higher score is more anomalous.
At `0.52`, the confusion matrix is:

| Actual \ Predicted | Normal | Attack |
|---|---:|---:|
| Normal | 249 | 1 |
| Attack | 147 | 3 |

The candidate `0.492817` was derived as the 90th percentile of anomaly scores
on the 250 normal validation rows, targeting the configured 10% normal
false-positive rate. It was then evaluated on the separate labeled holdout:

| Actual \ Predicted | Normal | Attack |
|---|---:|---:|
| Normal | 232 | 18 |
| Attack | 0 | 150 |

No attack labels were used to select that candidate threshold. The strong
holdout result can still reflect the simplicity and distribution of the
synthetic generator. The candidate is reported for analysis; the production
policy remains unchanged at `0.52`.

## SHAP check

Exact SHAP values were computed for one held-out synthetic normal row over the
same `decision_function` used for inference. The base value was `0.18826349`,
the model score was `0.09944157`, and the six contributions summed to the score
with absolute additivity error `1.39e-17`.

| Feature | SHAP value (rounded) | Direction for `decision_function` |
|---|---:|---|
| `total_bytes_sent` | -0.000200 | Anomaly push |
| `total_bytes_received` | +0.002989 | Normalizing |
| `connection_count` | -0.033581 | Anomaly push |
| `unique_dst_ports` | -0.003139 | Anomaly push |
| `unique_dst_ips` | -0.042388 | Anomaly push |
| `window_seconds` | -0.012504 | Anomaly push |

For this model output, higher `decision_function` values mean more normal, so
negative contributions push the score toward an anomaly. This single-row check
validates SHAP additivity for one synthetic example; it is not a global
explanation-quality assessment.

## Reproduce

From the repository root, with backend dependencies installed:

```powershell
python scripts/generate_synthetic_flow_data.py
$env:TRAINING_DATA_SOURCE = "synthetic_smoke_test"
python -m backend.app.ml_engine.flow_model.train
python scripts/evaluate_flow_model.py --csv data/evaluation/synthetic_labeled.csv
```

The checked-in artifact is
`data/model_artifacts/flow_model_v2_synthetic.pkl`. It is deliberately named
`synthetic` and is not loaded by the backend's default model path. For a
meaningful model assessment, replace these generated rows with clean captured
traffic for training and held-out real benign and attack windows for
validation.
